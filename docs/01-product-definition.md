# 产品定义与边界

## 一句话定位

Moyusi 是面向 AI 编程工具用户的多源模型路由、算力供给、统一结算与工作环境迁移平台：用户在模型广场选择闭源 API 或开放模型部署，在工作台完成本地路由、Key、模型部署、WorkspaceProfile、用量、计费与账户管理。

## 不是简单相加

CC Switch 解决“本机如何切换与路由”，模型中转平台解决“云端从哪里获得模型与如何计费”。Moyusi 的产品价值是把二者之间最容易出错的一段——复制 Key、判断协议、选择模型 ID、部署开放模型、修改配置、迁移工作环境、验证请求——收敛为可信闭环。

```text
传统路径
购买额度/算力 → 创建 Key/端点 → 查文档 → 找 Base URL → 猜协议 → 改配置 → 重启 → 测试

Moyusi
选择模型与供给 → 选择工作环境 → 确认权限与变更 → 首次调用成功
```

## 目标用户

### 核心用户：多工具 AI 开发者

- 同时使用 2 个及以上 AI 编程工具。
- 因价格、限流、可用性或模型能力需要切换供应商。
- 不想理解每个工具的配置文件和环境变量差异。
- 需要知道“这次调用用了哪个模型、哪条线路、多少钱”。

### 次级用户：小团队负责人

- 希望为项目或成员分配 Key、额度和模型权限。
- 需要月度用量、成本和异常提示。
- 不希望把上游主 Key 发给每位成员。

### 后续用户：独立应用开发者

- 需要统一 API 和多上游容灾。
- 更看重 SDK、管理 API、项目级预算和稳定性。
- 此类能力可以在个人用户闭环稳定后扩展。

## 核心 Jobs to Be Done

1. 当我想尝试一个模型时，我希望在 3 分钟内看懂价格并在现有工具中完成首次调用。
2. 当主线路限流或故障时，我希望在我允许的范围内自动切换，并知道实际走了哪条线路。
3. 当我担心费用失控时，我希望设置明确的额度、到期时间和告警，而不是事后看到账单。
4. 当我更换电脑、模型或软件时，我希望迁移路由、MCP、Skills、Prompts、经审核记忆和知识来源，同时重新绑定而不是暴露第三方凭证。
5. 当我需要使用开放权重模型时，我希望按需选择共享端点、专属部署或自有算力，并看懂许可、版本、性能、冷启动和费用。
6. 当价格或模型版本变化时，我希望变化可解释、可追溯，不影响已经发生的账务。

## 产品承诺

### 1. 两个产品面

- 模型广场负责闭源 API 与开放模型的选型、不同供应或部署来源比较和接入。
- 工作台负责 CC Switch 式本地路由，以及 Key、模型与部署、工作环境、用量、计费、设备和账户。

两者使用同一账号和同一信息结构，不再单独设置“我的”。

### 2. 一次选择

用户选择的是“模型 + 供给/部署方式 + 工作环境 + 目标工具”。系统负责生成正确的协议、Base URL、模型映射、资产适配和本地配置。

### 3. 每一笔可解释

调用记录至少能解释：谁、何时、使用哪个 Key、请求哪个模型、实际路由、输入/输出计量、采用哪个价格版本、扣了多少钱。

### 4. 本地与云端边界清楚

- 云端：账号、平台 Key、模型目录、线路、部署元数据、可选的加密工作环境资产、计量、账本、订单。
- 本地：工具配置、第三方 BYOK/资产 Secret、配置备份、Target Adapter、本地代理状态。
- 默认不把第三方 Key 上传到 Moyusi 云端。
- 工作环境包只同步 Secret reference；目标设备重新授权和绑定 Secret。

## 产品原则

1. **少即是清楚，不是少信息。** 隐藏低频操作，但价格、线路、协议、权限和风险不能藏。
2. **先成功调用，再展示增长模块。** 首屏不放邀请、返佣、公告瀑布和活动横幅。
3. **一个产品面一个目标。** 模型广场负责选择；工作台通过轻量子导航完成路由和管理，不把所有模块同时铺在一屏。
4. **默认安全。** Key 只显示一次，导入令牌短时有效，日志默认不存请求/响应正文。
5. **默认透明。** 不把完全不同的模型静默当成同一模型回退。
6. **价格是数据，不是文案。** 定价必须版本化、可测试、可回溯。
7. **不把“可运行”当“可销售”。** 上游授权、区域、内容政策与付款规则是发布条件。

## MVP 范围

### 必须有

- 邮箱或 OAuth 登录。
- 可筛选的语言/代码模型目录。
- 至少一条共享开放模型线路，并可连接一个用户自有 OpenAI-compatible 开放模型端点。
- 每条线路标明统一余额、BYOK 或供应商直连，并显示来源、价格、健康、地区和数据政策。
- 开放模型展示 revision、权重来源、许可、量化、推理引擎、硬件、冷启动与部署计费方式。
- 每个模型的协议、上下文、输入/输出价格、线路等级与数据处理说明。
- 预付额度或单一充值方式。
- 平台 API Key 的创建、命名、限额、到期与吊销。
- OpenAI Responses、Chat Completions、Anthropic Messages 三类端点。
- Codex、Claude Code 两个桌面工具的一键接入；Gemini CLI 可作为第三个。
- 首次调用检测与可读错误提示。
- 用量、费用、余额和逐请求元数据。
- 管理端模型、线路、价格版本、账户、订单、网关健康与人工调账。
- Codex、Claude Code 的 Provider Profile、一键切换、本地代理、回退、熔断、原子写入和恢复。
- Codex、Claude Code 的最小 WorkspaceProfile：MCP、私有 Skills 和 Prompts 的导入、版本、部署、diff 与回滚。

### 明确不进入 MVP

- 图片/视频工作台。
- 公共 MCP/Skills 市场、复杂在线编辑器和社区分发。
- 跨软件会话进程、隐藏推理、厂商缓存或私有工具状态的无损恢复。
- P0 中的任意 GPU 云编排、自动记忆提取和完整知识库平台。
- 团队席位、组织层级与复杂 RBAC。
- 自动选模、跨模型家族的语义路由。
- 上游 BYOK 云端托管。
- 邀请、返佣、优惠券、订阅矩阵和多币种。
- 模型训练、微调、数据集管理。
- 面向第三方模型供应商的自助开放市场入驻；首批供应商仍由人工签约和准入。

## 关键边界

### “模型 API 购买”

对用户文案统一解释为购买以下一种权益：

- 可消费的预付额度；或
- 有效期明确的套餐额度；或
- 明确 SLA 的专属容量。

不得使用“购买模型”暗示模型所有权、官方账号、永久使用权或未经证实的官方线路。

### “官方”和“稳定”

- `官方直连` 只用于 Moyusi 与模型厂商存在可证明的直接商业/技术关系时。
- `稳定线路` 必须有公开的路由范围和内部 SLO，不能只是营销标签。
- `高性价比` 必须显示取舍，例如可能更高延迟、较低优先级或可重试场景。

### 故障转移

- 同一模型在多个授权上游间切换可以默认开启。
- 模型别名到同一模型版本的兼容映射可明确展示后开启。
- 跨模型家族回退必须由用户或项目显式配置，并在响应元数据中返回实际模型。

## 成功指标

### 北极星指标

`每周完成至少一次有效 API 调用的已连接设备数`

该指标同时要求云端购买/Key 和本地工具接入都真正工作，比注册数、充值额或下载量更能代表产品闭环。

### MVP 指标

| 指标 | 目标 |
| --- | --- |
| 新用户从注册到首次成功调用的中位时间 | ≤ 3 分钟 |
| 模型页到“接入成功”的转化率 | ≥ 40% |
| 一键接入流程成功率 | ≥ 95% |
| 网关月度可用性目标 | ≥ 99.9%（正式承诺需另行签署） |
| 账本与上游日结差异 | < 0.1%，且可解释 |
| Key 泄漏导致的重大安全事件 | 0 |
| 与价格错误相关的有效投诉 | 0 |

## 仍待业务确认

1. 运营主体与首发地区。
2. 上游采购和转售授权模式。
3. 首发支付方式、结算币种、税费和发票。
4. 余额是否过期、退款窗口和套餐是否结转。
5. Moyusi 的正式中英文品牌、域名和商标可用性。
6. 桌面端是否完全开源、部分开源或闭源分发。
