# 模型中转与网关平台第二轮调研

调研日期：2026-08-28  
重点样本：[ModelFlare Origin](https://origin.modelflare.dev/zh)、[禾维 AI / Hvoy](https://www.hvoyai.com/)  
对照样本：[OpenRouter](https://openrouter.ai/)、[302.AI](https://302.ai/)、[Vercel AI Gateway](https://vercel.com/docs/ai-gateway)、[AIHubMix](https://aihubmix.com/models)

## 1. 先说结论

这轮调研把“做得好”拆成了五种不同能力，不能用一个总榜代替：

1. **ModelFlare 最值得参考首次购买与接入闭环**：一个 Key、模型分组、三步调用、Codex/CC-Switch 接入、逐请求费用，产品叙事完整。
2. **OpenRouter 最值得参考路由与市场透明度**：Provider、价格、延迟、吞吐、数据策略、回退都能成为可编程条件。
3. **302.AI 最值得参考中文用户的“API 超市”与教程体系**：搜索、分类、在线调试和第三方工具教程降低了接入门槛，但产品范围远大于 Moyusi MVP。
4. **Vercel AI Gateway 是企业网关基线**：统一协议、预算、观测、自动路由和无加价定价的语义很清楚，但它不是面向中国个人开发者的充值型中转站。
5. **Hvoy 不是模型供应商，而是评测、目录、排行与导购层**：它证明中转市场真正稀缺的不是模型列表，而是对真实性、稳定性、价格和运营主体的可验证信号。

因此，Moyusi 不应定位为“另一个模型很多、折扣很低的站”。更有价值的定位是：

> 用可验证线路销售模型访问能力，并把购买、Key、本地工具接入、实际路由、用量与资金解释成一条链。

## 2. 调研边界与证据等级

- `一手观察`：本次在浏览器中实际打开的官网、产品页、文档、隐私页和公开仓库。
- `平台自述`：产品自己对可用性、安全、模型来源或用户量的声明，未做独立审计。
- `第三方信号`：Hvoy 的探测、排行、认证和评论；只作为线索，不作为供应商准入结论。
- `推断`：从页面和文档提炼的 Moyusi 产品/工程决策。
- 价格、模型、榜单、促销、域名和政策都高度易变；本文不推荐用户按快照充值。

Hvoy 页面本身也明确说明，其检测是多轮技术探测，不是法律意义的审计，也不保证百分之百准确，并建议首次只做最低限度充值。[Hvoy](https://www.hvoyai.com/)

## 3. 市场分层

```text
模型厂商 / 授权推理商
        ↓
聚合与中转市场       OpenRouter / ModelFlare / AIHubMix / 302.AI
        ↓
企业 AI 网关          Vercel AI Gateway / LiteLLM 类
        ↓
本地工具控制面        CC Switch / Moyusi Desktop

旁路验证与导购        Hvoy：探测、排行、目录、评论、套餐内容
```

Hvoy 与 ModelFlare 不是同类竞品：前者帮助用户判断“该信谁”，后者向用户出售“如何调用”。Moyusi 需要拥有自己的线路监测和证据展示，但 MVP 不需要复制一个面向全行业的第三方排行榜。

## 4. 深度样本

### 4.1 ModelFlare Origin：最接近 Moyusi 商业闭环

#### 一手观察

- 首页直接使用“一个网关 / 多个模型分组”“一个 Key”“用量 + 计费”建立心智。[首页](https://origin.modelflare.dev/zh)
- 页面把一次请求画成客户端 → 网关 → 模型，并同时展示路由、状态、延迟、Token 和相对官方价格。
- 当前公开目录在同一页展示 25 个可用模型、厂商筛选、兼容 API 和每个模型的路线分组；数量只代表本次快照。
- 以代码模型为例，分组被表达为价格优先、稳定、高级等层级，并展示缓存命中率保障与相对官方价格。
- 首次调用被压缩为创建 Key、设置 Base URL、发起请求三步；Codex 示例进一步压缩为安装脚本与模型参数。
- 用量区强调按应用/工具分配 Key、逐请求状态/延迟/Token/费用，以及有序备选分组。
- 文档包含 Codex、Claude Code、Gemini CLI、OpenCode 和 [CC-Switch 配置](https://modelflare.dev/zh/docs/cc-switch)。
- 信任页说明默认不把完整请求/响应正文作为长期业务记录，短期诊断记录设计为 72 小时，并明确没有宣称 SOC 2/ISO 27001、标准服务不支持 HIPAA。[信任与安全](https://modelflare.dev/zh/trust)

#### 做得好的地方

- **先讲调用结果，再讲平台能力**：用户很快能理解 Key、模型、路由、费用的关系。
- **路线分组是可购买产品**：路线不是后台黑盒，而是用户能比较和选择的报价。
- **工具接入不是文档尾页**：Codex/CC-Switch 被放进主购买路径。
- **费用能落到单次请求**：这比只给余额曲线更能建立信任。

#### 暴露出的机会

- 首页促销横幅先于首次调用，会把“便宜”置于“可信”之前。
- “官方价格的 x%”容易让用户误以为线路来源、服务等级也与官方等价；需要同时说明来源类别、限制、数据处理和回退范围。
- `award / stable / premium` 仍是平台自定义命名，若没有窗口、样本量、SLO 和补偿计算说明，用户很难跨平台比较。
- 一行安装脚本极其省事，但安全敏感用户会希望先看脚本、变更预览、签名/校验和与卸载方式。

#### Moyusi 应如何吸收

- 复用“一 Key、三步首次调用、逐请求账单、工具接入”的结构。
- 将每条路线升级为**可核验线路卡**：来源声明、协议、实时价格、价格版本、7/30 天成功率、p50/p95、样本量、最后探测时间、缓存规则、数据留存、允许的回退范围。
- 一键导入必须先展示配置 diff；网页只传一次性票据，不把 Key 放入 URL 或安装命令。
- 首次成功调用前不展示充值促销、邀请返佣或升级套餐。

### 4.2 Hvoy：中转站市场的“信任搜索引擎”

#### 一手观察

- 首页允许输入 API 地址、API Key 和目标模型做检测，解释会结合协议结构、知识表现、身份一致性、推理痕迹和签名指纹做交叉判断。[首页](https://www.hvoyai.com/)
- 页面明确提醒优先使用测试专用 Key，也明确技术检测不是法律审计、不能保证百分之百准确。
- [排行榜](https://www.hvoyai.com/leaderboard/)按模型展示站点、分组、价格、30 天价格趋势、Token 消耗、在线率、“掺水率”、延迟和运行状态。
- 榜单上付费位置明确标记“广告”，这是必要但还不充分的利益冲突披露。
- [站点目录](https://www.hvoyai.com/sites/)与详情页聚合主体认证、模型/分组、公告、历史探测和用户评论。
- 页面同时提供官方模型状态、模型择优、Coding Plan/Token Plan 对比和免费 Token 等内容，已经从检测工具扩展为流量与导购平台。
- 其公开仓库 README 明确写道“具体的检测代码，已经不开源了”，因此当前算法、权重与探测实现不能由公开仓库完整复核。[公开仓库 README](https://github.com/zzsting88/relayAPI#readme)
- [隐私协议](https://www.hvoyai.com/privacy/)称不把 API Key/完整凭据作为账号资料保存，同时也说明可能处理请求内容、设备/一般使用记录及运营、安全、合规所需信息，保留期按合理需要确定。

#### 做得好的地方

- **把用户真正担心的风险做成列**：价格低不再是唯一排序维度。
- **同一模型横向比较路线**：避免站点首页各说各话，逼近真实购买决策。
- **短期与趋势结合**：实时在线、延迟与 30 天价格趋势比静态“99.9%”更有信息量。
- **广告显式标记**：至少让用户知道哪些位置可能受商业关系影响。
- **强风险提示**：反复提醒小额充值和经营风险，符合行业现实。

#### 不能直接当事实的部分

- “模型一致”或“掺水”是启发式判断，不等于上游授权证明、模型厂商证明或法律鉴定。
- 在线率、延迟高度依赖探测地区、频率、超时、请求内容和样本量；页面总分不能替代方法说明。
- 企业/个人认证只能说明某种主体核验，不证明资金安全、长期运营、上游合法性或 SLA。
- 评论是用户陈述，存在样本偏差、刷评和争议处理问题。
- 广告已标记，但“精选”排序、推荐文章与返利链接仍需要公开权重和商业关系，才能证明排名独立性。
- 首页“端对端加密、用后即焚”的短文案不能单独证明实现；隐私政策的处理范围和留存描述更宽，应以经过审计的技术与政策共同判断。

#### Moyusi 应如何吸收

- 不做“靠谱分”，直接展示原始、带时间窗口的证据。
- 把**商业主体、供应关系、技术健康、数据政策、用户反馈**分成五类，禁止互相替代。
- 线路上线前做内部合成探测；线上请求只用于匿名聚合的被动指标，默认不查看正文。
- 若以后提供第三方 Key 检测，必须使用一次性、低权限测试 Key，公开探测请求、数据流、删除机制和方法局限。
- 广告、赞助、返佣永远不进入默认排序因子；付费位置必须单独分区和标记。

### 4.3 OpenRouter：路由透明度与市场机制标杆

#### 一手观察

- 一个 API 访问大量模型，并把 Provider 路由作为正式 API 能力。[Models](https://openrouter.ai/docs/guides/overview/models)
- 请求可以控制 Provider 顺序、是否回退、数据收集、ZDR、量化、价格上限、参数支持，以及按价格、吞吐或延迟排序。[Provider Routing](https://openrouter.ai/docs/guides/routing/provider-selection)
- 默认路由结合近期故障与价格，模型页面和接口还公开延迟/吞吐等指标。
- 官方 FAQ 当前称推理价格透传、购买 Credits 收费，BYOK 在免费额度后另有服务费；均属易变商业规则。[FAQ](https://openrouter.ai/docs/faq)
- Provider 入驻文档要求声明模型、价格、能力、上下文、量化、数据中心、容量和可用性，并描述性能如何影响流量。[Provider Integration](https://openrouter.ai/docs/guides/community/for-providers)

#### Moyusi 应如何吸收

- 数据模型按 `Model → Provider/Channel → RouteOffer → PriceVersion` 分层。
- 内部路由引擎保留丰富策略，MVP UI 只暴露“稳定 / 低价 / 指定线路”三个清楚选择。
- 每次响应与账单返回请求模型、实际模型、实际线路、回退次数和价格版本。
- 数据留存、区域与模型能力必须是路由约束，不能只是信任页文案。

### 4.4 302.AI：中文 API 超市与内容化接入

#### 一手观察

- 首页把产品定义为按用量付费的企业级 AI 资源平台，同时提供应用超市、API 超市、客户端和模型排行。[首页](https://302.ai/)
- API 超市覆盖语言、图片、视频、音频、信息检索、RAG 等多类资源；语言模型再按大量厂商细分。
- 官方帮助中心从分类浏览、选择 API、在线调试到复制 Key 形成教程链。[API 在线调试](https://help.302.ai/docs/API-shi-yong)
- API 文档以统一域名和常见兼容格式给出请求/响应示例。[API 文档](https://doc.302.ai/)
- 官方 CLI/Skill 文档把图片、视频、语音、3D、音乐和搜索包装成 Agent 可调用命令，并支持按请求 ID 查询账单。[CLI Skill](https://doc.302.ai/)

#### Moyusi 应如何吸收

- 采用面向任务的搜索，例如“给 Codex 接入代码模型”，而不只按厂商筛选。
- 每个模型保留可直接运行的在线测试和复制示例，但测试费用、路线和数据处理必须先显示。
- 建立按 Codex、Claude Code、Gemini CLI、OpenCode 分类的接入文档。
- 不复制“应用超市 + API 超市 + Agent + 多媒体工作台”的宽产品面；MVP 只服务代码/语言模型与本地工具闭环。

### 4.5 Vercel AI Gateway：企业网关的产品语义

#### 一手观察

- 官方文档将产品表述为单一端点访问大量模型，并提供预算、用量监控、负载均衡和回退。[Overview](https://vercel.com/docs/ai-gateway)
- 支持 AI SDK、OpenAI Chat Completions/Responses、Anthropic Messages 等接口，协议选择被清晰放入文档结构。
- 默认 Provider 选择结合近期可用性和延迟，用户可以设置 Provider 顺序、白名单和回退行为。[Provider Options](https://vercel.com/docs/ai-gateway/models-and-providers/provider-options)
- 当前定价页称按 Provider 列表价、按量计费、无加价，并提供 Credits；商业规则仍需实施前复核。[Pricing](https://vercel.com/docs/ai-gateway/pricing)

#### Moyusi 应如何吸收

- 模型 ID 采用稳定命名空间，区分模型创造者与实际服务 Provider。
- 状态、预算和观测是网关主能力，不应该被增长模块淹没。
- 网关文档按协议与模态组织；控制台模型页按用户任务组织，两种导航不要混为一套。
- Vercel 面向已有开发团队，Moyusi 还必须补上中文支付、额度解释、本地工具自动配置和个人用户风险提示。

## 6. 把 Hvoy 指标改造成可开发的产品字段

| 市场信号 | 能说明什么 | 不能说明什么 | Moyusi 的实现 |
| --- | --- | --- | --- |
| 在线率 | 特定窗口内探测成功比例 | 正式 SLA、未来可用性 | 显示 1h/24h/30d、样本量、探测地区和超时阈值 |
| 延迟 | 特定请求路径的响应速度 | 所有用户地区和任务的体验 | 分地区展示 TTFT 与总时延 p50/p95 |
| Token 差异 | 计量或模型行为可能异常 | 单独证明模型被替换 | 同时保留标准化计量、上游原始计量和本地 tokenizer 估算 |
| 模型一致性探测 | 返回协议/能力存在异常线索 | 上游授权和法律意义的模型真伪 | 标记“通过 / 异常 / 样本不足”，公开探测版本和局限 |
| 价格趋势 | 路线成本是否频繁变化 | 下一次调用最终价格 | PriceVersion 带生效时间，调用前读取确定版本 |
| 主体认证 | 运营主体有可核验身份 | 线路合法、不会停运、服务可靠 | 与供应授权、技术健康、财务风控分开展示 |
| 用户评论 | 个体使用问题与客服线索 | 统计事实或平台结论 | MVP 不做评论；以后需购买验证、申诉和审核机制 |

禁止使用以下未经定义的标签：`满血`、`官池`、`纯享`、`无水`、`企业级`。若业务需要展示，必须转换成可验证合同：模型版本、能力矩阵、上下文、速率、来源类别、SLO、数据处理和补偿条件。

## 7. 对 Moyusi 的新增产品要求

### P0：首发就要有

1. **线路证据卡**：价格之外，显示最近窗口健康、样本量、协议、数据处理、价格版本和最后核验时间。
2. **测得与承诺分离**：`过去 24h 成功率 99.92%` 是测量；`月度 SLA 99.9%` 是合同；页面不能混写。
3. **调用可追溯**：每次请求能看到 requested/actual model、route、fallback、Token、cache、latency、price version、amount。
4. **状态页**：公开网关和模型族状态、历史事件、影响范围与恢复时间。
5. **信任页**：主体、上游关系类别、数据生命周期、退款、故障补偿、支持渠道和政策更新时间。
6. **安全接入**：一次性设备绑定导入票据、配置变更预览、连接测试和可回滚备份。

### P1：公测阶段

1. 合成探测服务：协议、工具调用、流式、超时、计量、模型能力一致性。
2. 路线健康历史：地区、p50/p95、成功率、错误分布、熔断和价格变化。
3. 用户自助诊断：使用平台签发的短时测试 Key，不要求提交第三方长期主 Key。
4. 路线切换前比较：价格变化、数据政策变化、性能变化和回退范围变化。

### P2：有规模后再做

- 第三方站点目录、公共排行榜、用户评论、优惠码、套餐导购。
- 若未来做这些功能，运营收入与技术排序必须制度和代码双重隔离。

## 8. 上游/路线准入框架

Hvoy 可用于发现线索，但 Moyusi 不能根据第三方榜单直接采购或上线。每条路线至少经过以下门禁：

1. **主体与授权**：合同主体、付款主体、服务地区、转售/代理范围、模型和商标使用权。
2. **协议合同测试**：非流式、流式、取消、工具调用、结构化输出、错误码、用量与缓存字段。
3. **模型一致性**：能力测试只作为异常检测；关键授权仍以供应链文件和上游对账为准。
4. **计费核验**：平台 tokenizer 估算、上游 usage、账单和实际扣款可对齐。
5. **健康压测**：多地区成功率、TTFT/总时延、并发、限流、长输出、故障恢复。
6. **数据处理**：正文是否记录、诊断字段、保留时间、子处理方、跨境、删除与事件响应。
7. **运营准备**：状态通知、工单时效、余额/退款、域名与端点变更机制。

任一路线在“授权不清、计费不可解释、模型静默替换、数据政策缺失”时不得标记为稳定线路；严重项应阻断上线。

## 9. 设计方向

ModelFlare 的深色工程感和 Hvoy 的高密度数据表都有效，但 Moyusi 不应原样复制。

- 公共首页只回答三个问题：能用什么、怎么接入、为什么可信。
- 模型页默认只显示模型、用途、最终价格、健康摘要和“接入工具”。
- 展开后再显示路线证据，不在首屏堆满 Provider、倍率、缓存、地区和协议术语。
- Hvoy 式全量排行榜适合研究模式；Moyusi 默认是 10–20 个策展模型和少量可解释路线。
- 广告、充值活动和公告不进入首次调用主路径。
- “便宜”使用金额表达，“稳定”使用窗口与样本表达，“安全”使用数据流和控制措施表达。

## 10. 本轮决策

| 决策 | 结论 |
| --- | --- |
| Moyusi 是否做公开中转站榜单 | MVP 不做；只做自营路线证据与状态 |
| 是否使用 Hvoy 排名选择上游 | 只作线索，不作准入证据 |
| 首发是否追求模型数量 | 否；10–20 个代码/语言模型 |
| 是否展示综合“靠谱分” | 否；展示带窗口、样本和方法的原始指标 |
| 是否提供模型真实性承诺 | 只承诺可证明的模型/供应关系；启发式探测单独标注 |
| 是否加入促销与返佣 | 首次调用前不加入，MVP 不做 |
| 核心差异化 | 线路可核验 + 桌面工具安全接入 + 调用到账本可追溯 |

## 11. 开发前仍需外部确认

1. 首发路线的合同、授权链与允许销售地区。
2. “官方直连”“授权转售”“聚合供应”等公开措辞的法务标准。
3. 公开健康指标是否涉及供应商保密条款。
4. 退款、SLA 补偿、余额有效期、税费和发票规则。
5. 合成探测是否允许使用各上游服务，以及探测内容与频率限制。
6. 默认元数据、短期诊断和账务记录的具体保留期限。
