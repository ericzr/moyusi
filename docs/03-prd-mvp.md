# Moyusi MVP 产品需求文档

版本：0.1  
状态：开发前基线  
日期：2026-08-28

## 1. MVP 目标

验证一个核心假设：AI 编程工具用户愿意在同一产品内获得闭源额度或开放模型端点，并通过一次明确授权把模型和最小工作环境接入本地工具；“接入成功、可迁移与持续使用”比单纯模型低价更能建立留存。

## 2. 信息架构

### 未登录

```text

/market

```

### 已登录产品

```text
/market                    模型广场：选模型、比较多来源线路、加入工作台
/workspace                 工作台：路由、API 与来源、模型部署、工作环境、用量计费、账户
```

工作台内部允许使用子路由或分段状态，但站点一级导航只显示「模型广场」「工作台」。Key、用量、账单、设备和账号不再各占一级入口。

### 工作台桌面端

```text
模型                        已连接的 Moyusi 模型与平台 Key
工具                        Codex / Claude Code / Gemini CLI
供应商                      Moyusi 与本地 BYOK Provider
部署                        共享开放模型、专属端点与自有算力
工作环境                    Profiles、MCP、Skills、Prompts
用量                        本机请求状态与云端费用摘要
设置                        代理、网络、备份、更新、关于
```

MVP 只加入服务于迁移闭环的私有 MCP、Skills 和 Prompts Profile，不做公共市场、复杂在线编辑器或厂商会话进程的无损恢复；完整度仍聚焦 Provider、开放模型端点与工作环境的可靠切换。

## 3. 核心流程

### Flow A：从模型到首次调用

1. 用户打开模型广场。
2. 选择模型，进入详情查看协议、上下文、输入/输出价格和多供给来源。
3. 选择具体供给；统一余额、BYOK、共享/专属算力和自有端点分别进入计费、授权或预算确认。
4. 统一余额不足时先充值，完成后返回当前模型和供给；配置草稿不因跳转丢失。
5. 若无可用平台 Key，创建一个默认 Key，可设置金额上限和到期时间。
6. 选择 Codex 或 Claude Code。
7. 如果桌面端未安装，进入下载页；已安装则发起一次性导入授权。
8. 桌面端显示将修改的工具、Base URL、模型和权限；用户确认。
9. 桌面端原子写入配置并做连接测试。
10. 成功页只显示三项：已接入工具、模型、查看用量。

### Flow B：充值与扣费

1. 用户选择固定金额充值。
2. 服务端创建 PaymentIntent/Order，前端跳转支付。
3. 只以经过验证的支付回调入账，客户端返回页不直接加余额。
4. 账本生成 `topup` 贷记，派生余额更新。
5. 每次完成调用生成计量事件，结算后生成 `usage_debit`。
6. 余额不足时拒绝新请求；流式请求按预留额度和最终用量结算。

该流程只适用于标记为“统一余额”的签约线路。BYOK 线路由供应商直接扣费，Moyusi 只展示供应商回传值或明确标注的本地估算。

### Flow C：线路故障转移

1. 请求根据模型、协议、Key 权限、地区和用户线路偏好生成候选集合。
2. 先尝试首选线路；仅在允许的错误类上回退。
3. 同一模型的备用线路可以自动尝试。
4. 跨模型回退只有用户显式配置才允许。
5. 响应头/元数据和用量页显示实际模型、实际线路与是否发生回退。

### Flow D：吊销泄漏 Key

1. 用户在工作台的“API 与来源”中点击吊销。
2. 系统立即使新请求失效，不等待缓存过期。
3. 页面给出创建替代 Key 和重新同步已连接设备的入口。
4. 审计日志记录操作者、时间、Key 前缀和原因，不记录明文。

### Flow E：接入开放模型

1. 用户在模型广场选择标记为“开放权重”的模型。
2. 比较共享端点、专属部署和“连接自有端点”；查看 revision、许可、量化、引擎、硬件、冷启动、隐私与计费方式。
3. 共享端点可直接加入路由；自有端点需要绑定 Secret reference 并完成协议/能力探测。
4. 系统把模型工件和实际 ServingRevision 分开记录，能力不兼容项不得静默忽略。
5. 首次调用后显示实际权重修订、服务引擎、端点、计量和价格版本。

### Flow F：迁移工作环境

1. 用户选择一个 WorkspaceProfile 和目标软件/版本。
2. 桌面端发现目标配置并生成资产兼容性矩阵。
3. 用户重新绑定目标环境需要的 Secret，查看 MCP/Skill 权限与字段级 diff。
4. 桌面端备份后原子写入，并验证模型、MCP、Skills 与知识来源。
5. 迁移报告逐项标记 `exact`、`adapted`、`rebuilt` 或 `unsupported`。
6. 任一阻断验证失败时回滚；不能用“部分同步成功”代替明确结果。

## 5. 页面级要求

### 模型广场

- 默认按“适合代码工作”策展排序，不默认按折扣最高排序。
- 每行只显示：模型、关键能力、协议、起始价格、线路状态、接入。
- 展开或详情页再展示各线路、缓存价、上下文、限制和数据边界。
- 价格必须显示计费单位与更新时间。
- “稳定”必须同时显示统计窗口和样本量；“SLA”只用于有合同定义、计算规则和补偿条件的承诺。
- 开放模型行使用“开放权重”标识，展开后比较共享、专属和自有端点；模型卡与部署卡分开。
- 开放模型详情必须显示许可、revision、量化、引擎、硬件、热/冷状态和部署费用，不只展示参数量。

### 工作台

- 默认打开总览，只显示当前工具、活动路由、余额/外部计费状态和需要处理的告警。
- 子导航固定为：路由、API 与来源、模型与部署、工作环境、用量与计费、账户。
- 路由模块支持 Provider Profile、排序、切换、模型映射、健康、回退、熔断和本地代理。
- API 与来源模块区分 Moyusi 平台 Key、本地 BYOK 与已连接供应商账号。
- 用量与计费模块合并原 Key、用量和账单页面的查询入口，但每个详情区仍只有一个主操作。
- 账户模块承载登录安全、设备、会话、通知、偏好、发票和隐私，不设“我的”一级页面。

### 工作台 · 模型与部署

- 默认只显示正在使用或需要处理的端点，不做 GPU 资源大盘。
- 共享端点主操作是“加入路由”；自有端点是“连接”；专属端点是“创建部署”。同一区域只保留一个主操作。
- 状态必须区分配置完成、正在拉取权重、正在启动、健康、缩容到零、错误和已停止。
- 专属部署同时显示当前小时成本和预计月成本；外部 BYOC 费用标记为供应商账单或估算。

### 工作台 · 工作环境

- 首屏以 Profile 为单位，显示已部署目标、版本、最近同步和需要处理的兼容问题。
- MCP、Skills、Prompts、记忆和知识库作为 Profile 详情分段，不成为站点一级入口。
- 迁移确认只展示目标、变更、权限和不支持项；高级字段按需展开。
- 不把 exact、adapted、rebuilt 和 unsupported 合并成一个“同步成功”状态。

### 工作台 · API 与来源

- 主操作仅一个：“创建 Key”。
- 默认 Key 不等于无限权限；默认设置月度软告警，用户可继续收紧。
- 完整 Key 只在创建成功弹窗展示一次，并提示保存位置。
- 不提供“再次显示”；只提供轮换或重新创建。

### 工作台 · 用量与计费

- 首屏四个指标以内：本期费用、请求数、成功率、剩余额度。
- 列表不展示提示词和响应正文。
- 每条记录可展开查看路由、计量、错误类别、时延和账本流水 ID。

### 工作台 · 余额与账本

- 余额和“充值”是主操作。
- 流水按资金语义显示：充值、调用、退款、赠送、调账、过期。
- 账单与活动公告分离。

## 6. 错误体验

| 错误类别 | 用户文案原则 | 可执行动作 |
| --- | --- | --- |
| Key 无效/已吊销 | 明确哪个 Key 前缀，不暴露明文 | 创建/替换 Key |
| 权限不足 | 说明被禁止的模型或协议 | 编辑范围 |
| 余额不足 | 显示余额和预估最低需求 | 充值 |
| 模型不存在 | 区分输入 model id 错误与已下线 | 复制当前 model id |
| 上游限流 | 显示是否已回退、预计可重试 | 重试/换线路 |
| 协议不兼容 | 说明工具和目标端点不匹配 | 重新接入正确协议 |
| 本地配置冲突 | 显示冲突字段和备份位置 | 预览合并/恢复 |

## 7. 非功能要求

- Web 控制台 p75 LCP < 2.5 秒；模型目录支持缓存与增量更新。
- 网关自身新增 p95 延迟目标 < 100 ms，不含上游耗时。
- 任何日志、追踪、分析和错误上报均不得包含完整 Key。
- 默认不存请求/响应正文；如果未来提供可选归档，必须单独授权、加密、可删除、有明确期限。
- 所有金额使用整数最小货币单位或高精度 Decimal，不使用浮点数。
- 所有时间存 UTC，界面按用户时区显示。
- 生产变更、定价发布、人工调账和权限提升有审计日志。
- Web、Gateway、Worker、Desktop 均有结构化版本号和可回滚发布。

## 8. 发布验收

MVP 只有同时满足以下结果才算完成：

1. 一个全新用户能在干净机器上从模型目录完成 Codex 或 Claude Code 首次调用。
2. 重复支付 webhook、重复 API 请求和客户端重试都不会重复入账或重复扣费。
3. 任一调用都能从请求 ID 追到计量事件、价格版本和账本流水。
4. 吊销 Key 能在所有网关节点及时生效。
5. 上游失败时，系统只按用户允许的策略回退，并展示实际线路。
6. 默认日志中不存在完整 Key、支付凭证或请求/响应正文。
7. 价格变更前后的调用都能按各自版本正确重算。
8. 桌面端写配置失败时原文件未损坏且可恢复。
9. 任一对外“稳定”状态都能追到主动/被动样本、窗口、阈值和最后更新时间。
