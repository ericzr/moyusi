# CC Switch 逐页能力矩阵与 Moyusi 工作台开发主线

状态：已完成截图核对，作为后续开发基线  
日期：2026-08-29  
范围：用户提供的 19 张 CC Switch 页面截图（13:24:48–13:26:05）

## 1. 先给结论

CC Switch 是 Moyusi 当前的主要竞品和能力参照对象。它的页面很多，但用户真正依赖的是四个能力闭环：

1. **Provider 能被统一描述、添加、排序和切换**；
2. **路由能在本机执行，并且故障可检测、可回退、可恢复**；
3. **网页配置能安全落到本机工具，且不破坏原配置**；
4. **MCP、Skills、Prompts、会话等工作资产可以被索引、同步和迁移**。

Moyusi 不应复制 CC Switch 的六个设置页或几十个开关，而应把这些能力收敛为一个工作台：

```text
模型广场选择模型/供给
  → 工作台生成 RouteProfile
  → Desktop Bridge 发现工具并预览变更
  → 用户确认后备份、原子写入、连接测试
  → Gateway/本地路由器执行切换与回退
  → Usage Ledger 记录实际模型、线路和费用
  → WorkspaceProfile 携带 MCP / Skills / Prompts / 会话检查点
```

截图中的“供应商”在 Moyusi 中必须拆成三个对象：

- `Source`：可选的模型供给来源，可能是 Moyusi 统一余额、BYOK、供应商直连或自有端点；
- `ProviderProfile`：某一个目标工具如何使用该来源；
- `RouteProfile`：多个来源的优先级、回退、地区和数据规则。

这样可以避免把“模型来源”“本机工具配置”和“路由策略”混在同一个表单里。

## 3. 能力取舍矩阵

优先级含义：

- **P0**：Moyusi 的“模型 → 接入 → 切换”闭环没有它就不成立；
- **P1**：公测前应有，先做最常用的 Codex/Claude Code；
- **P2**：规模化后再做，不能阻塞主线；
- **不做 Web**：能力可保留，但只能由 Desktop 执行或暂不承诺。

| 能力 | P0/P1/P2 | Moyusi 设计 | 第一版验收 |
| --- | --- | --- | --- |
| Provider 列表、排序、启用 | P0 | 来源列表与工具 Profile 分离；当前路由只显示一个清晰主状态 | 选择一个来源后能生成可恢复的 RouteProfile |
| 预设 Provider | P0 | 策展 10–20 个来源；显示协议、模型映射、结算方式和健康证据 | 预设可一键生成连接草稿，不要求用户填写 TOML |
| 自定义 Provider | P1 | 基础表单只保留名称、地址、Secret、默认模型；协议细节放“高级” | 能探测协议和模型，并返回可读错误 |
| 统一 Provider | P1 | `UnifiedProviderProfile` 一次编译到多个目标适配器 | Codex 与 Claude Code 至少能生成逐字段 diff |
| 项目作用域 | P1 | 路由、资产和预算可绑定个人/项目；项目切换不改变全局默认值 | 切换项目后当前 RouteProfile 和资产版本可追踪 |
| 本地路由服务 | P0 | Desktop loopback 服务；网页只保存策略版本 | Desktop 可启动/停止，网页显示心跳和端口状态 |
| 自动故障转移/熔断 | P0 | 只对同一模型、声明过的错误类回退；跨家族需显式允许 | 429/超时/可恢复 5xx 可按顺序回退并记录原因 |
| 整流器/协议转换 | P0 | 网关和本地适配器分别声明能力，不做静默魔改 | Responses、Chat Completions、Anthropic Messages 合同测试通过 |
| 全局出站代理 | P1 | Desktop 网络设置；默认关闭，显示风险和作用范围 | 代理失败有 DNS/TLS/认证分类，不泄露 Secret |
| OAuth/官方登录 | P1 | 只保存授权引用和状态；保留官方登录选项 | 切换第三方来源不会覆盖官方登录，能恢复 |
| 应用发现与升级 | P1 | Desktop 扫描已安装工具和版本；网页展示结果 | Codex/Claude Code 未安装、可升级、无法运行三态明确 |
| 备份、原子写入、回滚 | P0 | 所有本机变更前自动快照；失败自动恢复 | 模拟写入失败后配置与路由均回到变更前 |
| Token/费用统计 | P0 | 汇总卡片只展示决策必需指标；详情可下钻 | 能按模型、来源、时间查到请求和费用 |
| 请求日志 | P0 | 作为调用证据，不冒充账本；默认不存正文 | 每条记录有 request id、实际模型、线路、延迟、状态 |
| 账本/充值/退款 | P0（统一余额） | 服务端不可变账本；BYOK 显示外部估算 | 支付重放不重复入账，余额不足能回到原接入上下文 |
| MCP 管理 | P0（私有） | 资产列表、权限、目标应用和迁移状态；公共市场后置 | Codex/Claude Code 可导入、diff、部署、回滚 |
| Skills 管理 | P0（私有） | ZIP/Git 导入、版本、脚本风险提示、目标应用状态 | 安装失败不破坏原 Skill；同步结果逐项可见 |
| Prompts 管理 | P0（私有） | Markdown/变量/启用状态；编辑器不进首屏 | 能导入、版本化并为目标工具生成适配结果 |
| 会话索引/恢复 | P1 | 先做元数据和 resume 检查点，不承诺厂商隐藏状态无损迁移 | 可筛选项目、查看来源、生成恢复/不支持报告 |
| 记忆与知识库 | P1/P2 | 先迁移引用、权限和索引状态；内容迁移需审核 | 不把第三方私密正文默认为可上传 |
| 主题/语言/托盘/开机自启 | P1（Desktop） | 偏好在工作台统一管理；OS 动作由 Desktop 执行 | Web 与 Desktop 状态不混淆，离线时显示待处理 |
| WebDAV/云同步/诊断日志 | P2 | 先做平台工作环境版本；通用云同步后置 | 不阻塞模型接入与路由闭环 |

## 4. Moyusi 工作台建议信息架构

一级产品面仍然只有“模型广场”和“工作台”。工作台内部建议采用**五组、十个目的页**，避免 CC Switch 那样把设置拆成平级大页：

```text
工作台
├─ 开始
│  ├─ 总览                 /workspace/overview
│  └─ 模型切换             /workspace/routing
├─ 接入
│  ├─ 来源与凭证           /workspace/sources
│  ├─ 模型与部署           /workspace/deployments
│  └─ 工具与设备           /workspace/tools
├─ 工作环境
│  ├─ 配置与迁移           /workspace/environment
│  └─ 会话                 /workspace/sessions
├─ 费用
│  ├─ 用量与请求           /workspace/usage
│  └─ 余额与账单           /workspace/billing
└─ 设置
   └─ 偏好、数据与安全     /workspace/settings
```

现有 `/workspace/account` 可保留为兼容别名，未来并入“设置”；现有 `/workspace/billing` 可继续承载余额和账单，但用量请求应从账户页中独立出来。这样既不破坏已发布 URL，又能逐步收敛导航。

### 4.1 总览

只回答四个问题：当前使用什么、是否可用、今天花了多少、下一步做什么。保留 Desktop 连接状态、当前 RouteProfile、待处理迁移/授权和最近一次请求；不放完整设置表格或营销指标。

### 4.2 模型切换

分成“简单模式”和“高级设置”：

- 简单模式：目标工具、当前模型、主来源、备用来源、策略（自动/固定/成本优先）；
- 高级设置：地区、错误分类、熔断、代理、协议整流、请求正文留存。

Provider 卡片只显示用户要做的选择；`auth.json`、`config.toml` 和模型字段映射放进目标工具的 diff 抽屉。

### 4.3 来源与凭证

以“我能否使用这个来源”作为主线，而不是以供应商名称作为主线：

- Moyusi 统一余额：可直接加入路由；
- BYOK：引导 Desktop 绑定系统安全存储；
- 供应商直连：显示外部计费和授权状态；
- 自有端点：进入端点探测与模型发布；
- 新增来源：先选预设，最后才显示自定义配置。

API Key 只显示前缀、权限、额度和最近使用时间；明文只在创建瞬间交给用户或 Desktop。

### 4.4 工具与设备

把截图中的“应用检测、升级、首选终端、开机自启、托盘、本地路由”集中到设备页。网页展示设备、平台、版本、在线状态和待处理动作；Desktop 执行扫描、安装、升级和 OS 级设置。

### 4.5 配置与迁移

统一资产列表使用五个轻量筛选：`MCP / Skills / Prompts / 记忆 / 知识库`。每项都显示版本、目标应用、权限、最近同步和迁移结果。默认动作是“生成迁移计划”，而不是立即覆盖本地文件。

### 4.6 会话

先做 Session Index：项目、工具、模型、来源、时间、resume id、是否可恢复。点击后显示对话摘要和迁移报告；对于加密内容、厂商隐藏状态或不兼容格式，明确标记 `unsupported`，不伪装成完整恢复。

### 4.7 用量与请求 / 余额与账单

把 CC Switch 的统计卡片和请求表保留，但拆开“证据”和“资金事实”：

- 用量与请求：Token、延迟、首字、状态、实际来源、回退原因；
- 余额与账单：充值、预留、扣费、退款、价格版本、账本流水。

BYOK 费用必须单独显示为“外部估算/供应商回传”，不能混入 Moyusi 余额。

## 5. 后续开发主线

### Phase 1：工作台信息架构与领域契约（1 周）

交付：

- 将现有七个子域映射到五组导航，新增 `tools`、`sessions`、`usage` 的路由占位；
- 冻结 `Source`、`ProviderProfile`、`UnifiedProviderProfile`、`RouteProfile`、`ToolTarget` 类型；
- 为每页补齐 loading、empty、error、stale、offline 五类状态；
- 把所有演示 fixture 移到 `fixtures/`，页面只依赖 repository。

退出标准：刷新和深链后，用户可以从模型广场回到同一个工作台上下文；导航不会出现“钱包/账号”重复入口。

### Phase 2：Provider + Route 纵向切片（2–3 周）

交付：

- 预设来源选择、来源探测、模型能力和协议合同；
- RouteProfile 编辑、候选来源排序、同模型回退、暂停策略；
- Codex/Claude Code 两套 ProviderProfile fixture；
- 变更预览、备份、原子写入和回滚的 mock 流程；
- 连接测试错误分类（DNS/TLS、认证、协议、模型、额度、上游）。

退出标准：完成“选模型 → 选来源 → 生成路由 → Desktop 确认 → mock 调用 → 用量记录”。

### Phase 3：Desktop Bridge 与应用发现（2–3 周）

交付：

- 设备注册、一次性 ImportGrant、心跳和离线状态；
- Codex/Claude Code 的本地配置发现与版本检测；
- 系统安全存储中的 SecretBinding；
- loopback 路由服务、启动/停止、端口和代理状态；
- 备份快照列表和一键恢复。

退出标准：网页从不读取本机 Secret；Desktop 离线时，所有本机动作都显示为“等待连接”，不伪装成已执行。

### Phase 4：WorkspaceProfile 与会话（3–4 周）

交付：

- MCP、Skills、Prompts 的统一资产索引、版本、导入和目标适配器；
- 权限 diff、脚本风险确认、目标应用安装状态；
- Session Index、resume 检查点和迁移报告；
- 记忆/知识库先支持引用、权限和索引状态，内容重建单独确认。

退出标准：同一 Profile 在 Codex 与 Claude Code 间完成一次可解释迁移，结果逐项标记 `exact/adapted/rebuilt/unsupported`。

### Phase 5：用量、账本与诊断（2–3 周）

交付：

- 请求事件、实际模型/来源/价格版本、延迟和回退原因；
- 用量查询、请求日志、余额、充值和账本的分离接口；
- BYOK 外部费用估算与统一余额扣费的不同展示；
- 连通性检测、应用诊断日志和供应商健康窗口。

退出标准：任意一笔费用都能从用户请求追到 RouteOffer、PriceVersion 和 LedgerTransaction，且支付/结算事件幂等。

### Phase 6：偏好、同步与生态（P2）

交付：

- 语言、主题、首选终端、托盘、开机自启；
- 多设备非敏感配置同步、备份恢复、导入导出；
- Gemini CLI、OpenCode 等更多目标工具；
- 公共 MCP/Skills 市场和供应商自助入驻（需另立合规与审核项目）。

## 6. 第一轮实现任务（建议按此顺序编码）

1. 增加 `WorkspaceSection`：`tools`、`sessions`、`usage`，并保留旧路径重定向。
2. 建立 `Source`、`ProviderProfile`、`RouteProfile`、`ToolTarget` 的 schema 和 mock repository。
3. 将“来源管理”从当前静态 `Sources` 页面改为“状态列表 + 新增来源向导”两步流程。
4. 将路由页拆为简单模式和高级抽屉，加入主来源/备用来源的真实排序状态。
5. 增加 `DesktopAppInstallation` fixture，覆盖已安装、未安装、无法运行、可升级四态。
6. 增加配置 diff、备份快照、回滚结果的可视化组件，不直接展示完整 Secret。
7. 把 MCP/Skills/Prompts 从一个“环境”空壳提升为统一资产表，先接入导入、启用和迁移预览。
8. 增加 Session Index 和请求日志的读取模型，明确“日志不等于账本”。
9. 用一条 Playwright 流程锁住：模型详情 → 工作台来源 → 路由保存 → Desktop 离线提示 → 恢复连接。
10. 每次切片结束运行 `pnpm typecheck`、`pnpm test`、`pnpm build`、`git diff --check`。

## 7. 明确不照搬的部分

- 不把通用设置做成六个平级大标签页；低频设置进入“设置与数据”或 Desktop；
- 不让用户默认编辑 `auth.json`、`config.toml`；只展示必要字段和字段级 diff；
- 不把“供应商数量”当作价值指标；用户首先要看到的是可用模型、价格、延迟和可恢复性；
- 不在网页中模拟本机安装、升级、写文件、托盘和代理；
- 不默认上传第三方 Key、会话正文或知识库私密内容；
- 不做跨模型家族的静默回退；
- 不在主导航加入钱包、账号、设置等新的一级产品面；
- 不在主线未闭环前建设公共市场、社区评价、复杂团队 RBAC 或自动记忆提取。

这份矩阵与 [13-web-desktop-boundary.md](./13-web-desktop-boundary.md)、[14-stage2-route-control.md](./14-stage2-route-control.md) 一起作为 CC Switch 能力复用和后续前端开发的基线。
