# Web 与桌面端边界决策

> 结论：Moyusi 采用“网页主产品 + 轻量桌面桥接”的双层形态。网页负责发现、比较、购买、路由策略、工作环境管理与迁移预览；桌面端只负责本机工具接入、敏感凭证落盘和本地代理运行。

## 1. CC Switch 能力拆解

根据 [CC Switch 官网](https://ccswitch.io/zh/) 与 [公开仓库 README](https://github.com/farion1231/cc-switch)，CC Switch 的价值不只是一个模型选择页面，而是本机控制面：

- 管理 Claude Code、Claude Desktop、Codex、Gemini CLI、Grok Build、OpenCode、OpenClaw、Hermes 等工具的配置；
- 50+ Provider 预设，一键导入、排序、切换和导出；
- 本地代理、格式转换、自动故障转移、熔断、健康检查和请求修正；
- 系统托盘快速切换、自动启动、自动更新和跨平台桌面分发；
- MCP、Skills、Prompts 的跨工具同步，以及会话浏览/恢复和 Workspace 文件编辑；
- SQLite 持久化、原子写入、自动备份，避免配置损坏。

其中前两类是产品编排能力，后几类依赖操作系统权限、进程生命周期或本地文件系统。

## 2. 能力边界

| 能力 | 网页端 | 轻量桌面桥接 | 说明 |
| --- | --- | --- | --- |
| 模型目录、同型号来源比较 | 负责 | 不需要 | 适合搜索、价格、延迟、健康度和可用性解释 |
| 充值、统一余额、账单和用量 | 负责 | 不需要 | 以服务端账本为准，BYOK 单独标记 |
| 路由规则、优先级、回退策略 | 负责配置 | 负责落地 | 网页生成版本化策略，桌面原子写入本机工具 |
| API Key/端点绑定 | 负责授权流程 | 保存本机 Secret | 第三方明文 Key 默认不上传 Moyusi |
| 修改 Claude/Codex 等配置文件 | 不可靠 | 必须 | 浏览器沙箱不能稳定访问任意本地路径 |
| loopback 本地代理与热切换 | 不能直接提供 | 必须 | 需要监听本机端口、守护进程和进程健康状态 |
| 系统托盘、开机启动、自动更新 | 不支持 | 必须 | 属于操作系统级能力 |
| MCP/Skills 文件安装与扫描 | 可做目录和 diff | 执行安装/回滚 | 含脚本的 Skill 需要本地扫描、权限确认和回滚 |
| 会话迁移 | 可做导入、解析、检查点 | 读取/写入本地会话 | 不承诺跨厂商隐藏状态无损恢复 |

因此，“只做网页”可以覆盖模型广场和大部分工作台管理，但无法完整复刻 CC Switch 的本机切换体验。试图在网页中完成这些动作，最终仍会变成安装一个本地代理或浏览器扩展，安全边界反而更模糊。

## 3. Moyusi 形态决策

### 网页是默认入口

用户打开 Moyusi 先进入模型广场：按语言/图片/视频，再按开源/闭源，比较同型号不同来源的价格、延迟、稳定性和计费方式。工作台是右侧唯一的管理入口，承载路由、来源、部署、工作环境、费用和账户。

网页在没有桌面端时仍然可用：用户可以购买额度、生成平台 Key、管理路由草稿、查看用量、导入 WorkspaceProfile 并生成迁移报告。

### 桌面端是按需安装的桥

只有用户点击“接入本机工具”“启用本地代理”或“应用迁移”时，才提示安装 Moyusi Desktop。安装后通过一次性、短时效 ImportGrant 与网页配对：

1. 网页生成不含明文 Secret 的变更预览和一次性票据；
2. 桌面端校验票据、展示目标工具/文件/权限 diff；
3. 用户确认后，桌面端将 Secret 写入系统安全存储，配置采用备份 + 原子替换；
4. 桌面端回传结果、连接测试和可恢复版本，网页更新工作台状态。

网页 URL、日志和 Profile 导出包不携带第三方明文 Key。桌面端离线时，网页仍保留所有云端管理能力，并明确显示“等待本机确认”。

### 当前前端表达

工作台已将这一边界直接表达为连接状态：网页负责模型发现、来源比较、账户/费用和路由策略；Moyusi Desktop 负责本机密钥、第三方软件配置写入、本地代理和回滚。Desktop 的“本机已连接 / Desktop 离线 / 未安装 Desktop”状态会出现在工作台侧栏、总览和路由页。离线时，页面不会把本机配置写入或模拟调用显示成可执行动作。

## 4. 开发主线

1. **Web MVP**：模型广场、来源比较、统一充值/账单、平台 Key、路由策略编辑、WorkspaceProfile 和迁移 diff。
2. **Desktop Bridge**：先支持 Codex 与 Claude Code；实现设备注册、一次性导入、配置备份/原子写入、连接测试和本地状态心跳。
3. **Local Runtime**：加入 loopback 代理、健康检查、自动回退和托盘快捷切换；策略版本由网页管理，执行状态由桌面端上报。
4. **Portable Workspace**：扩展 MCP、Skills、Prompts、会话检查点和知识库适配器，所有迁移结果区分原样、转换、重建和待确认。

## 5. 取舍原则

- 不把 CC Switch 整个桌面控制台复制进网页；网页只呈现用户需要做的决策。
- 不为了“无需安装”牺牲本地凭证安全和配置可恢复性。
- 桌面端保持轻量、可选、可卸载；没有桌面端时，云端功能不被阻塞。
- 先交付“选模型 → 统一结算 → 路由生效 → 本机确认 → 可追溯用量”这一条闭环，再扩展更多工具和资产类型。
