# 原型清理与复用决策

日期：2026-08-28

## 结论

旧原型不适合作为产品结构直接延续，但其中有一组克制、工具化的视觉原则值得保留。当前实现已合并为「模型广场」与「工作台」两个一级产品面，并开始按 catalog/workspace 领域拆分。

判断标准只有三个：是否帮助用户做出模型/线路选择，是否缩短本地工具接入路径，是否让价格、健康、用量和资金更可验证。不能回答这三个问题的界面元素不进入 MVP。

## 保留并沿用

| 原型特征 | 沿用方式 | 理由 |
| --- | --- | --- |
| 黑白中性色与低饱和状态色 | 作为深浅主题基础，绿色只表示正常证据 | 能承载高信息密度，不制造营销感 |
| 细边框、低阴影、少层级 | 表格、卡片和弹层统一使用 | 让信息结构而非装饰成为主角 |
| 等宽字体 | 仅用于模型 ID、价格、路径、请求 ID | 技术字段更易扫描，同时避免全站“终端风” |
| 紧凑表格 | 用于模型目录、调用记录、账本 | 重复字段多，横向比较优于营销卡片 |
| 分段导航 | 一级只保留模型广场、工作台；管理功能进入工作台子导航 | 降低站点层级，同时保留任务边界 |
| 分组卡片与主从详情 | 模型广场先用语言/图片/视频分组，再以目录 + 供给详情比较线路 | 保留原型的信息组织能力，不继承旧业务语义 |
| 从目录发起接入 | 模型行保留唯一主操作“接入” | 符合“选择后立即使用”的核心闭环 |
| 配置预览 | Web 只说明目标路径和字段，真实写入在桌面端确认 | 同时降低操作成本和凭证风险 |

## 保留意图、重做结构

| 旧意图 | 当前重做 | 不直接沿用的原因 |
| --- | --- | --- |
| 模型市场 | 策展模型目录 + 线路等级 + 24h 证据 | 折扣优先会掩盖稳定性、协议与数据新鲜度 |
| 供应商控制台 | Codex / Claude Code 的本地连接状态 | 上游凭证管理与本机工具配置是不同安全领域 |
| 用量可视化 | 14 日简洁柱图 + 可追溯请求行 | 大面积点阵热图缺乏计费决策价值，也形成错误领域联想 |
| 个人中心 | 余额、遮蔽 Key、账本最小集合 | 账户页应服务资金与凭证，不承载促销或无关设置 |
| 模态详情 | 线路证据和接入确认两个明确弹层 | 每个弹层只解决一个决定，避免全能抽屉 |

## 已删除或迁出

- 旧占位品牌、域名、样式 token 和相关文案。
- 气候地图、空气/过敏指标、热力点阵、截图素材和数据辅助函数。
- 设计工具自动导出的绝对定位组件与大量未使用 UI 封装。
- Figma 原型里缺少资产模型、权限和迁移语义的图片/视频创作页，以及 MCP、Prompts、Skills、Sessions、导入/导出页面结构。图片与视频只作为模型广场的任务分类回归；创作画布不恢复。未来工作环境能力按 `WorkspaceProfile` 重做，不恢复这些旧页面。
- 看似真实的供应商 Key、固定钱包金额操作和折扣优先排序。
- 外部字体请求、重复全局样式、无使用的构建插件和依赖。

这些内容没有留在源码归档目录中，避免搜索、构建和新成员阅读时继续形成噪声。迁出副本只用于短期恢复，不是产品参考源。

## 当前实现边界

- 这是交互原型；模型、价格、健康、余额、Key、请求和账本均为演示数据。
- 网页不会写入真实本机配置，也不会在 URL 中传递 Key。
- 真实产品仍需桌面端的变更预览、原子写入、备份恢复和安全存储。
- 生产目录必须由服务端 Catalog、RouteOffer、PriceVersion 与证据窗口驱动。
- 生产余额必须由不可变账本派生，不能沿用前端数值状态。

## 视觉与结构验收

- 桌面端：模型目录在首屏展示主要决策字段，健康证据和接入操作可达。
- 390px 窄屏：主导航、搜索、筛选和模型行可操作；宽表格保留横向滚动，不压缩技术字段。
- 深浅主题：语义和层级一致，状态不只依赖颜色。
- 信息密度：每页一个主任务；没有大渐变、营销横幅、装饰图或无意义动效。

## 下一步开发约束

1. 继续把工作台骨架拆成 routing、sources、deployments、workspace-profile、billing 等领域组件；禁止重新把生产逻辑堆回 `App.tsx`。
2. 把演示常量移到独立 fixture，并用 mock API 驱动页面。
3. 先实现“模型 → 平台 Key → 桌面确认 → 首次调用”的无资金闭环。
4. 线路健康必须显示样本窗口、新鲜度和未知状态，不能只给装饰性百分比。
5. 支付、账本和真实上游只在授权、地区、退款与留存规则冻结后接入。
