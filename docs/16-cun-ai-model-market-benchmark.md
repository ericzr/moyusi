# CUN.AI 模型广场调研与 Moyusi 吸收方案

调研日期：2026-08-29  
样本页面：[CUN.AI 模型广场](https://www.cun.ai/pricing)

## 1. 结论

CUN.AI 做得好的地方不是模型卡片本身，而是把“这个模型能不能买、为什么值得买、如何比较”拆成了可扫描的字段：

- 总模型数、搜索和分组入口在首屏形成目录心智。
- 左侧筛选同时覆盖供应商、模型标签、定价类型、端点类型，并显示每个选项的数量。
- 模型卡片同时展示输入、输出、缓存价格，以及分组、计费方式、延迟、吞吐、成功率、协议和能力标签。
- 详情弹窗继续展开基础价格、分组价格、上下文、最大输出、模态、能力、厂商、许可证和数据保留。
- 标准/充值、/1M /1K、名称排序和列表/卡片切换被放在结果工具栏，属于“查看方式”而不是模型筛选。

这说明 Moyusi 当前模型广场的问题不是视觉简陋，而是目录层缺少足够的可比较证据。极简不应等于只显示一个起始价格和一个稳定性百分比。

## 2. CUN.AI 可复用的结构

本轮进一步核对了模型详情的“概览 / 性能 / API”三个分区。它们不是重复展示，而是对应三个连续决策：

1. **概览**：模型是谁、价格怎么算、支持什么能力、有哪些供应商分组。
2. **性能**：每个分组的 TPS、平均首 Token 延迟、平均延迟、成功率和时间窗口。
3. **API**：协议切换、cURL/Python/TypeScript 示例、认证头、参数表和速率限制。

一级页面也有一个重要的布局原则：左侧是可折叠的筛选面板，右侧是结果工具栏和模型卡片。价格单位、排序和列表/网格属于结果工具栏；供应商、标签、定价类型和端点类型属于筛选面板，二者不混在一排按钮中。

### 2.1 筛选层

| 维度 | CUN.AI 表达 | Moyusi 采用方式 |
| --- | --- | --- |
| 任务类型 | 模型广场全量目录 | 保持语言 / 图片 / 视频一级切换 |
| 供应商 | 左侧供应商清单 + 数量 | 增加紧凑供应商下拉，数量由目录计算 |
| 标签 | 上下文、Reasoning、Tools、Vision 等 | 保持精确筛选中的用途、协议、上下文等结构化字段 |
| 定价 | 按量计费、按请求 | 增加定价方式下拉；详情保留输入 / 输出 / 缓存 |
| 端点 | Chat、Response、Anthropic 等 | 保持接口兼容筛选，生产版扩展为协议能力字段 |

### 2.2 结果层

CUN.AI 的结果卡片有三个值得保留的分组：

1. **价格**：输入、输出、缓存必须分开；“起始价格”只能做排序辅助，不能替代完整价格。
2. **性能**：延迟、吞吐、成功率必须带时间窗口或采样语义。
3. **能力与来源**：模型能力标签、供应商/分组、协议和上下文需要在同一条结果里出现。

Moyusi 已在目录数据中新增 `pricing` 和 `performance` 结构，并在列表与卡片中展示这些字段。当前值是演示证据，生产环境必须由 PriceVersion 与 ProbeWindow 服务提供。

### 2.3 详情层

详情页适合承载用户不需要每次都看的信息：

- 完整模型 ID、版本与上下文上限。
- 输入 / 输出 / 缓存的基础价格和来源分组价格。
- 能力矩阵、接口兼容、模态输入输出。
- 供应商、许可证、数据保留与接入文档。
- 同一模型不同来源的价格、延迟、健康、结算方式和回退范围。

Moyusi 不复制 CUN.AI 的全屏复杂控制台，而采用“紧凑列表 + 详情页 + 来源选择弹层”的三层结构：列表做筛选和比较，详情做理解，接入弹层做授权/充值/端点分流。

## 3. CUN.AI 不应直接照搬的部分

- 不追求一次展示 74 个或更多模型；Moyusi 首发仍以策展模型和可验证来源为主。
- 不把分组名、折扣或套餐促销当作稳定性证据。
- 不在默认排序中混入广告、赞助或返佣因素。
- 不把“成功率”显示成没有窗口、地区、样本量的装饰百分比。
- 不将第三方供应商名称直接等同于模型授权或模型真实性。

## 4. 当前实现变更

- `ModelOffer` 新增 `pricing` 与 `performance` 字段。
- `CatalogFilter` 支持 `providers` 与 `billingTypes`。
- 模型广场新增供应商和定价方式下拉筛选。
- 紧凑列表显示模型 ID、输入/输出价格、响应/吞吐、成功率和最近探测时间。
- 卡片视图显示模型 ID、价格、响应/吞吐、成功率、来源数量和协议。
- 模型详情新增接口、上下文、定价方式和可用能力摘要。
- 模型详情增加“概览 / 性能 / API 接入”三分区；性能区按来源比较吞吐、响应、成功率，API 区提供可复制的 cURL 示例和参数摘要。
- 一级页面改为“左侧筛选面板 + 右侧结果区”，并将供给类型、供应商、模型标签、定价方式、端点/地区、上下文/响应分组。
- 结果工具栏增加标准 / 每 1K 价格显示切换，避免把价格单位和筛选条件混为一谈。
- 演示目录保留独立 `CATALOG_OFFERS`，生产替换点明确为服务端目录和线路探测数据。

## 5. 生产数据模型约束

```text
Model
  ├─ ModelVersion
  ├─ Provider / Source
  ├─ RouteOffer
  │    └─ PriceVersion
  └─ ProbeWindow
       ├─ latency_p50 / latency_p95
       ├─ throughput
       ├─ success_rate
       ├─ sample_count
       ├─ region
       └─ checked_at
```

前端只消费已经归一化的目录字段，不自行计算真实价格、成功率或线路稳定性。用户看到的“推荐”只能由明确的策展规则生成，并与商业排序隔离。
